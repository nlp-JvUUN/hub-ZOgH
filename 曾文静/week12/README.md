## 一、作业思路：多轮对话的本质是给 agent 加「记忆层」

### 1.1 先看老师课件怎么讲

`agent教学.pptx` 把 Agent 定义为 **模型 + 记忆 + 工具 + 规划 + 循环**，其中记忆层专门回答
「多轮对话中 Agent 失忆」的问题（Slide 4、17、18）：

| 课件概念 | 含义 | 落地方式 |
|---------|------|---------|
| 短期记忆 In-Context Memory | 最近 N 轮对话消息拼进 Prompt | 受 Context Window 限制，存最近 N 轮 |
| 长期记忆 External Vector Store | 重要信息向量化入库、检索注入 | 突破长度限制（本作业用轻量事实表替代向量库） |
| 情景记忆 Episodic Memory | 具体事件序列（"上次查过什么"） | 本作业：滚动摘要 |
| 语义记忆 Semantic Memory | 抽象事实与概念（"城市→坐标"） | 本作业：关键事实表 |
| 读写时机 | 每轮开始**读**（组装上下文），每轮结束**写**（提取摘要/事实） | 见 `memory.py` |

课件还点出 ReAct 的局限（Slide 26）：**上下文随循环增长，长任务逼近 Context Window**——
所以多轮对话的工程重点不只是"记住"，更是"有节制地记"（窗口 + 压缩 + 事实化）。

### 1.2 看林书勤同学 week12 的做法（参考，不照抄）

他的思路（很标准）：把单轮 `run(question)` 的 `messages` 从函数局部变量提升为
`ChatAgent` 实例属性，每轮结束后把「用户问题 + 工具过程 + 最终回答」全部写回历史，
再配一个 REPL 循环。这是多轮对话的**最小正确实现**——核心思想（状态持久化）完全正确。

### 1.3 本作业的差异设计

在林书勤方案的基础上，针对课件指出的两个问题（上下文爆炸、无记忆管理）做工程化：

```
单轮（week11）                     多轮（本作业）
┌─────────────────┐               ┌─────────────────────────────────────┐
│ run(question)   │               │ chat(question)                      │
│ messages 局部变量 │   读记忆       │  ① memory.build_context()          │
│ 用完即焚         │ ───────────►  │     system + [滚动摘要] + [关键事实]  │
│                 │               │     + 最近 N 轮问答 + 当前问题        │
└─────────────────┘               │  ② ReAct 循环（week11 原样保留）      │
                                  │  ③ memory.end_turn()                │
                                  │     追加轮次 / 抽事实 / 滚动压缩       │
                                  │     + session_store 落盘（可恢复）     │
                                  └─────────────────────────────────────┘
```

**三个核心差异点（也是和同学作业拉开差距的地方）：**

1. **三层记忆而不是一条 messages 列表**
   - 短期窗口：最近 6 轮问答原文；
   - 滚动摘要：超窗旧轮被 LLM（或规则）压缩成摘要，摘要再参与后续压缩，
     对话无限长而 token 有界 —— 直接对应课件 Slide 26 对 ReAct 局限的解法；
   - 关键事实：每轮从工具结果抽取「城市→坐标/温度/AQI」事实单独存放，
     追问（"那空气质量呢"）直接命中事实，**不用重查工具**。
2. **工具中间过程不入长期记忆**：每轮只沉淀「问题 + 回答 + 事实」三样，
   上下文增长 O(轮数) 而非 O(token)，而林书勤方案会把每轮 Thought/Action/Observation
   全部堆进历史。
3. **会话级持久化 + 管理命令**：进程退出后 `/switch` 回来记忆仍在（JSONL 落盘），
   而林书勤的 `reset()` 只清内存、退出即丢。

### 快速开始

```bash
# ① 离线完整演示（零 API Key、零网络）：三个场景自动跑 + 自动判定
python run_demo.py

# ② 离线 REPL（模拟 LLM 自带跨轮记忆，可体验 /summary /facts /switch 等命令）
python multi_turn_chat.py --mock

# ③ 真实模型（DEEPSEEK_API_KEY；天气数据 Open-Meteo 免费无 Key）
export DEEPSEEK_API_KEY=sk-xxx
python multi_turn_chat.py                      # 真实天气接口
python multi_turn_chat.py --mock-tools         # 真实模型 + 离线工具（验证可复现）

# ④ 会话恢复：上次退出后继续聊
python multi_turn_chat.py --session <会话ID>    # ID 用 /list 查看

# ⑤ 单轮脚本模式（不进入 REPL，配合 --session 续接历史）
python multi_turn_chat.py --ask "宁德今天天气怎么样？" --session <会话ID>
```

### REPL 命令

| 命令 | 作用 |
|------|------|
| `/new [标题]` | 开启新会话（标题默认取第一句问题） |
| `/list` | 列出所有会话（按最近活跃排序） |
| `/switch <id\|序号>` | 切换会话（跨进程恢复记忆） |
| `/drop <id\|序号>` | 删除会话 |
| `/history [n]` | 回看最近 n 轮 |
| `/summary` / `/facts` / `/stats` | 检视记忆内部状态（摘要/事实/token 统计） |
| `/reset` | 清空当前会话记忆 |
| `exit` / `/exit` | 退出 |

## 三、核心设计细节

### 3.1 记忆读写时机（对应课件 Slide 18）

```
每轮开始（读）   build_context():
                  system 提示词尾部追加「[此前对话摘要]」与「[已掌握的关键事实]」块
                  + 最近窗口的 (问题, 回答) 对 + 当前问题
每轮结束（写）   end_turn():
                  ① 追加本轮 Turn（question/answer/tools）
                  ② rule_fact_extractor 从工具结果抽事实（含坐标反查城市）
                  ③ _compact_if_needed：超窗轮次滚动进摘要；token 超预算强制压缩
```

### 3.2 滚动摘要（情景记忆）

- 窗口设为 6 轮：第 7 轮开始时，第 1 轮被挤出窗口，交给 `summarizer`
  （真实模式 = LLM 压缩，mock 模式 = 规则模板）合并进既有摘要；
- 摘要自身也有 token 上限（预算的一半），防止摘要膨胀；
- 效果：20 轮长对话后，记忆里的正文始终只有 6 轮，上下文 token 被预算钳制
  （见 `docs/验证记录_mock离线.md` 场景 C：摘要从 0 增长到 260 tok 后封顶）。

### 3.3 关键事实（语义记忆）

- 工具层输出是结构化/半结构化文本（geocode 的 JSON、`温度：18.0°C`、`AQI：52（良）`），
  规则式抽取即可稳定获得事实，无需 LLM；
- 事实表全局去重、上限 50 条，注入 system 供模型消费；
- 跨轮价值：第二轮「那空气质量呢」从事实表拿到宁德坐标，**跳过 geocode 直接查 AQI**
  （场景 A 实测：工具调用 2 次 → 1 次 → 1 次）。

### 3.4 双驱动验证（延续 week11 的 mock 方法论）

| 驱动 | LLM 决策 | 工具执行 | 用途 |
|------|---------|---------|------|
| mock（默认） | StatefulMockPlanner：会**消费记忆块**的规则模拟器 | 离线数据集 | 确定性验证记忆逻辑，零成本可复现 |
| 真实模型 | DeepSeek / DashScope | Open-Meteo 或离线数据集 | 验证真实模型对记忆块的消费效果 |

关键点：mock 模拟器和真实模型看到**同一份上下文**（含摘要块/事实块），
所以 mock 能通过说明「指代消解、事实复用」的机制被验证，真实模型则验证其效果。

### 3.5 会话持久化（session_store.py）

- 每个 turn 一行 JSON 追加写入 `sessions/<id>.jsonl`（append-only，崩溃不损坏历史）；
- 每行带当时的 summary/facts 快照 → 重启后 `load_memory_records` 重建三层记忆；
- `_index.jsonl` 维护标题/时间/轮数，超 20 个会话按 LRU 淘汰最旧；
- 与同学常见做法（只存 question/answer 两列）的区别：我们连「事实表、摘要」一起存，
  恢复后追问「刚才那个 AQI 是多少」依然可答。

## 四、实测结果（详见 docs/）

| 场景 | 验证点 | mock 离线（确定性） | 真实模型 DeepSeek |
|------|--------|--------------------|-------------------|
| A 追问复用 | 指代消解 + 坐标复用 | 工具调用 2→1→1，全部判定 ✅ | 2→1→1：追问轮复用记忆坐标，无重复 geocode，全部判定 ✅ |
| B 纯记忆回答 | 事实层被模型消费 | 对比轮 0 工具调用 ✅ | 0 工具调用，回答「北京 12°C vs 上海 22°C，北京更冷」与事实一致 ✅ |
| C 长对话压缩 | 滚动摘要 + token 预算 | 20 轮后窗口仍 6 轮、摘要封顶约 222 tok ✅ | 第 6 问起连续 0 工具调用，LLM 把 14 轮旧对话压成 184 tok 摘要 ✅ |

关键现象：**真实模型在事实累积后主动停止调工具**（场景 C 共 17 次 0 调用回答），
说明注入 system 的「[已掌握的关键事实]」块确实被模型消费 —— 这正是多轮对话
相对单轮的量化收益：同样的问题，单轮每次都要 geocode + 查询，多轮复用记忆即可。

工程提示（实测发现）：LLM 滚动摘要偶尔会记错数值（如把 AQI 55 记成 52），
而规则式事实表是精确的 —— 所以设计上**事实表（机器可验证）与摘要（供参考）并存**，
追问优先命中事实表，这正是分层记忆的工程价值。

（`run_demo.py` 每个场景带自动判定；mock 模式为确定性结论，真实模式为抽样实录。）

## 五、与同学 week12 方案的对比

| 维度 | 林书勤 | 洪建宇 | 多数同学（session JSONL / Web UI） | 本作业 |
|------|--------|--------|--------------------------------|--------|
| 领域 | 课件金融 Agent | 课件金融 Agent | 课件金融 Agent | 本人 week11 天气 Agent（延续） |
| 记忆结构 | 单条 messages 全量堆积 | 单条 messages 全量堆积 | 只存 Q/A 两列 | 三层：窗口/滚动摘要/关键事实 |
| 上下文增长 | O(token) 无上限 | O(token) 无上限 | O(轮数) 但丢中间信息 | O(轮数) 且 token 有预算 |
| 持久化 | 无（退出即丢） | 无（退出即丢） | 有（Q/A 文件） | 有（含事实/摘要快照，可完整恢复） |
| 可验证性 | 人工对话截图 | 人工对话截图 | 人工对话截图 | 脚本自动判定 + 离线可复现 |
| 离线演示 | 无（必须 API Key） | 无（必须 API Key） | 无 | mock 全链路离线可跑 |

**从洪建宇同学方案中学到的两个好细节（已吸收）**：
1. **向后兼容的 `run()` 包装**：他保留 `run(question)` 单轮入口，让课件自带的
   `evaluate.py` 无需改动即可继续用。我提供了等价的 `--ask` 单轮脚本模式，
   配合 `--session` 可把多轮会话当单轮 API 用（脚本/批量场景）；
2. **`msg.model_dump()` 序列化消息**：历史里的 assistant 消息用 dict 而非对象，
   保证跨轮、跨进程可序列化（我的实现从构造起就用纯 dict，性质相同）。

**我的方案相对洪建宇/林书勤的剩余差异**：他们每轮把 Thought/Action/Observation
全量堆进 messages（上下文无限增长），且退出即丢；我做了三层记忆 + 预算压缩 +
会话持久化 + 自动验证——多轮对话的"可长可续可验证"三件事都覆盖了。

## 六、优化方向

- [ ] 事实表升级为向量检索（课件说的长期记忆：Faiss/Chroma），突破 50 条上限；
- [ ] 会话过期策略与多用户隔离（目前单机单用户）；
- [ ] 摘要触发从"轮数"升级为"真实 token 计数"（以 usage 字段为准）；
- [ ] 支持导出/导入对话记录（JSONL 已是标准格式，可直接做）；
- [ ] 把记忆层平移到课件金融 Agent 工具集（memory 与工具解耦，改 TOOLS 即可）。
