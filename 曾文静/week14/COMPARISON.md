# Week14 作业：Skill 优化前后对比报告

**Skill**：notes-consolidator（学习笔记整理器）—— 把零散、重复的中文学习笔记整理成
去重、无损、结构化的 Markdown。
**优化目标**：token 消耗 ↓ + 执行效率 ↑ + 质量不降（无损）
**语料**：skills/notes-consolidator/data/raw_notes.md（934 tokens，含 2 处完全重复、2 对近似重复）

---

## 一、核心数字（测量工具：bench/benchmark.py，tiktoken/cl100k_base）

| 指标 | v1（初版） | v2（第 1 轮优化） | v3（第 2 轮自进化） | v1 → v3 |
|------|-----------:|------------------:|--------------------:|--------:|
| SKILL.md 指令 tokens | 1194 | 342 | 496 | **-58.5%** |
| LLM 输入 tokens | 934（全文） | 1432（plan 膨胀 ❌） | 489（精简 plan） | **-47.6%** |
| LLM 输出 tokens | 686（重写整篇） | 828 | 156（仅决策） | **-77.3%** |
| **单次任务合计 tokens** | **2814** | **2602** | **1141** | **-59.4%** |
| 本地脚本耗时 | 0 ms（无脚本） | ~25 ms | ~72 ms | +72 ms（可忽略） |
| LLM 处理时长估算* | ~3.38 s | ~3.12 s | ~1.37 s | **-59%** |

## 二、质量对比（自动化断言，同口径）

| 质量指标 | v1 | v2 | v3 |
|----------|:--:|:--:|:--:|
| 唯一内容丢失（应=0） | 0 | 0 | 0 |
| 近似重复未合并（应=0） | 0 | **2 ❌** | 0 |
| 章节标题缺失（应=0） | 0 | 0 | 0 |
| 无损校验 --verify | 未内置 | 未内置 | **✅ 通过** |

**关键发现**：v2 虽然省了 SKILL token，却漏检 2 对"近似重复"（意思相同、用词不同），
输出中仍有两处重复段落 —— 第一次"优化"实际造成了质量回退。
v3 通过模糊去重 + `--verify` 门禁，把质量恢复并锁住。

## 三、优化手段拆解

| # | 手段 | 作用维度 | v3 收益来源 |
|---|------|---------|------------|
| 1 | SKILL.md 指令精简（去示例、去 Q&A、流程化） | token | -58% 固定开销 |
| 2 | 机械工作下沉脚本（切章节/统计/完全重复检测） | token+效率 | 不再用 token 换机械劳动 |
| 3 | 精简 plan（只含需判断内容，正文不进上下文） | token | 输入 -48%（v2 曾因 plan 膨胀反而 +53%） |
| 4 | 决策式输出（只写 decisions.json，正文由脚本组装） | token | 输出 -77% |
| 5 | 模糊去重（difflib 相似度 ≥ 0.72） | 质量 | 修复 v2 漏检 |
| 6 | --verify 无损门禁 | 质量/可维护 | 防止再次回退 |

## 四、执行效率

- **脚本侧（实测）**：v3 预处理+组装共 ~72 ms（语料 3.4KB），毫秒级；
  语料越大，脚本与 LLM 的耗时差距越明显。
- **LLM 侧（估算）**：单次任务 2814 → 1141 tokens，推理时长约 -59%；
  v3 全流程只让 LLM 做"判断题"（每对近似重复选一侧），不再做"抄写题"。
- **工具调用**：v1 = Read 全文 + Write 全文（2 次大 token 调用）；
  v3 = 脚本预处理 + Read plan + Write 决策 + 脚本组装 + 校验（LLM 只有 1 次小调用）。

## 五、扩展性验证（多语料）

单语料结论可能"碰巧"，用两份规模不同的语料交叉验证（bench/scaling.py）：

| 语料 | 正文 tokens | plan tokens | plan/正文 | v1 单次成本* | v3 单次成本 | 节省 |
|------|------------:|------------:|----------:|------------:|------------:|-----:|
| raw_notes.md（小） | 934 | 489 | 0.52 | 2828 | 1141 | **59.7%** |
| raw_notes_large.md（大） | 2339 | 769 | 0.33 | 5287 | 1484 | **71.9%** |

\* v1 输出按"正文 × 0.75"估算（小语料实测比例 686/934），v3 决策输出为实测 156 tokens。

**为什么语料越大省得越多**：v1 的成本与**正文规模线性相关**（全文进上下文 + 整篇重写）；
v3 的 plan 只与**需要判断的量**（章节数、重复对数）相关，正文本身不进上下文。
plan/正文 占比 0.52 → 0.33，正是这一点的直接证据。
（大语料 v3 决策输出为实测 decisions_large.json 的 343 tokens。）

## 六、结论

- **效果**：在**无损**前提下，单次任务 token 消耗 **-59.4%**（2814 → 1141），
  LLM 推理时长约 -59%，本地脚本耗时仅 ~72ms。
- **过程**：优化不是一次到位的 —— v2 表面省 token 实则质量回退，
  靠**测量 + 门禁**发现并修复，这是"自进化 Agent"的核心闭环：
  *执行 → 测量 → 反思 → 改写*。
- **可复现**：`PYTHONPATH=<tiktoken路径> python3 bench/benchmark.py`
  重新生成全部数字（原始数据见 bench/results.json）。
