## 一、先学习，再动手

### 1.1 课件要点梳理（《强化学习.pptx》第四部分「DeepSeek GRPO」）

| 课件核心观点 | 在本作业中的落点 |
|---|---|
| PPO 工程痛点：Actor/Critic/RM/Ref 四模型太重 | 本作业只有 **policy + ref 两个模型**（GRPO 无 Critic） |
| GRPO：用**组内平均奖励**代替 Critic：同一题采 G 条答案，高于组均值的强化、低于的抑制 | `train_grpo.py::group_advantages()`：`A = (r − mean)/std` |
| 可验证奖励（verifiable reward）：数学题答案 1/0 判定，无需奖励模型 | 算术题程序生成、程序判分，零成本零噪声 |
| PPO-Clip 刹车：`min(ratio·A, clip(ratio, 1±ε)·A)` | 逐 token 实现，ε=0.2 |
| R1 工作流：Base → RL → SFT → RL | 本作业最小版：**SFT → GRPO** |
| TRL 十几行代码启动 GRPO | 本作业拆开黑盒：采样、奖励、优势、clip、KL 全部手写 |

### 1.2 借鉴课件示例

- **课件 `grpo_arithmetic`**：沿用其"难度旋钮"方法论——用基线摸底选 **informative group rate**
  高的难度进训练集；沿用其复合奖励设计（正确 1.0 + 格式 0.2）、宽松解析、greedy/pass@8/格式率
  三件套评估指标。**不同点**：模型与框架全部独立实现（不用 TRL/Qwen2），任务阶梯自行标定。
  我用从零训练的小模型 + 受控算术题CPU 可跑），且我实现了 PPO-clip 目标与 informative-rate 选题方法论（他的损失无 clip）。

## 二、实现思路梳理

### 2.1 整体流水线（最小闭环）

```
data.py 程序化出题 → train_sft.py（SFT 基线）→ evaluate.py（基线摸底）
   → train_grpo.py（从零 GRPO）→ evaluate.py（同评估集复测）→ compare.py（对比表+曲线）
```

- **训练目标**：两位数进位加法（L2）；奖励 = 答案正确 1.0 + `<answer>` 格式 0.2
- **评估集**：4 个难度 × 300 题，seed=42 固定，训练前后同一份，可配对比较
- **总耗时**：SFT ~40s + 基线评估 ~90s + GRPO ~45s + 复测 ~90s，全流程约 5 分钟（CPU）

### 2.2 为什么用"程序化生成"的算术题

| 考虑 | 说明 |
|---|---|
| 奖励可验证 | `47+38=85` 由程序判定，不用奖励模型、不用人工标注——R1 系"可验证奖励 RL"的最小样本 |
| 难度可控 | 是否进位、几位数就是难度旋钮，可把基线精确调到"GRPO 可学习区间" |
| 资源友好 | 无 GPU 环境：2.7M 参数字符级 GPT，CPU 秒级推理 |
| 有泛化/边界可测 | 训 L2，测没训过的 L3（算法泛化）与 L4（能力边界） |

### 2.3 难度阶梯（probe 实测标定，非拍脑袋）

| 难度 | 内容 | 在 SFT | 定位 |
|---|---|---|---|
| L1 | 两位数不进位加法 | 40% | 保底题：验证 RL 不损伤已有能力 |
| L2 | 两位数进位加法 | 40% | **GRPO 主训任务**（基线 0.77，有对也有错 → 组内有方差） |
| L3 | 三位数不进位加法 | 15% | 泛化题：没训过，测"列式加法算法"能否迁移 |
| L4 | 两位数×两位数 | 5% | 能力边界：探针实测怎么训都 ≈0，测 RL 能否凭空造能力 |

### 2.4 GRPO 核心公式（手写实现，对照课件）

每步对 8 道题各采样 K=8 条回答（T=1.0，保证组内多样性）：

1. **组内优势**（替代 Critic）：`A_i = (r_i − mean(r)) / std(r)`；组内全对或全错（std=0）时 `A=0`，该组不产生梯度
2. **Clip 目标**（PPO 刹车）：`L = E[ min(ratio·A, clip(ratio, 1−ε, 1+ε)·A) ]`，`ratio = exp(logp_θ − logp_old)`
3. **KL 正则**（防漂移）：`L += β·KL(π_θ‖π_ref)`，ref = 冻结的 SFT 模型，k3 无偏估计，β=0.5
4. **奖励**：`r = 1.0×正确 + 0.2×格式`（格式权重故意小于正确分）
5. 更新配方：每批 8×8=64 条补全，小批量 32，单轮更新，lr=1e-5

### 2.5 关键工程决策（每个都是踩坑换来的）

| 决策 | 取值 | 原因 |
|---|---|---|
| 模型 | 字符级 GPT 6×192（2.7M） | CPU 秒级推理；算术字符表仅 31 个 token |
| SFT 学习率 | 6e-4 | **lr=3e-3 时深层模型陷"位置捷径"：只会照格式出数、学不会算法**（答案位 loss 卡在 2.3 随机水平；降到 6e-4 后一两个 epoch 即学会） |
| 生成位置对齐 | prompt 前置 BOS、按批内最大长度填充 | **训练序列以 BOS 开头，评估/采样的 prompt 必须同样以 BOS 开头**，否则所有位置错位一格，评估恒为 0 |
| 答案解析 | 取"第一个数字" | **温度采样下小模型常在正确答案后继续输出数字**，取最后一个数字会把"对的前缀"误判为错，污染 GRPO 梯度（修复后组采样正确率 0.38→0.61） |
| 组大小 K / 温度 | 8 / 1.0 | K 太小优势估计噪声大；T=1.0 保证组内多样性（GRPO 的"训练燃料"） |
| GRPO 步数 | 40（提前停止） | 训练曲线显示 40 步内 KL 保持 ~0.02、熵下降、正确率升到 0.91；**继续训练 KL 迅速爬升、熵回升、策略漂移崩坏**（50 步 0.84、60 步 0.65、80 步 0.32）——教材级"KL 漂移"现象 |
| 解析/采样可复现 | 全流程固定 seed | torch 采样 RNG 与数据 RNG 均固定，结果可复现 |

## 三、运行方法

```bash
# 环境：conda env py312（torch 2.6 / numpy / matplotlib），无其他依赖
cd src

python train_sft.py --steps 750     # ① SFT 基线（~40s）→ outputs/sft_ckpt/
python evaluate.py                  # ② 基线摸底 → outputs/baseline_probe.json
python train_grpo.py                # ③ GRPO 40 步（~45s）→ outputs/grpo_ckpt/ + train_log.json
python evaluate.py --model ../outputs/grpo_ckpt/grpo.pt \
                   --out ../outputs/post_train_probe.json   # ④ 同评估集复测
python compare.py                   # ⑤ 对比表 + 曲线 → outputs/figures/

# 或者一键：bash run_all.sh
```

## 四、实验结果

### 4.1 训练前后对比（同一评估集：4 难度 × 300 题，seed=42）

| 难度 | 在训练集 | 格式率 前→后 | greedy 正确 前→后 | pass@8 前→后 | informative 前→后 |
|------|:---:|---|---|---|---|
| L1 两位数不进位加法 | — | 0.00 → 0.00 | 0.97 → **0.99** | 1.00 → 1.00 | 0.32 → 0.30 |
| **L2 两位数进位加法** | √ | 0.00 → 0.00 | 0.77 → **0.92** | 0.90 → **0.97** | 0.63 → **0.70** |
| L3 三位数不进位加法 | — | 0.00 → 0.00 | 0.87 → **0.96** | 0.96 → **1.00** | 0.53 → 0.61 |
| L4 两位数×两位数 | — | 0.00 → 0.00 | 0.00 → 0.00 | 0.01 → 0.01 | 0.01 → 0.01 |

（`outputs/figures/accuracy_compare.png` 为柱状对比图；`train_curves.png` 为训练曲线。）

### 4.2 结果解读

1. **主训任务显著提升**：L2 greedy 0.77 → 0.92（+15pt），pass@8 0.90 → 0.97。
   注意基线 pass@8 已有 0.90——说明"答案在模型分布里存在但概率不够集中"，
   GRPO 干的正是**把分布里的正确性"聚拢"到 greedy 解码上**（训练熵 0.25 → 0.18）。
2. **没训过的 L3 也在涨（算法泛化）**：0.87 → 0.96。GRPO 强化的是"做对进位加法"的
   内部回路，而不是背题——列式加法算法迁移到了三位数。
3. **L1 无回退**：0.97 → 0.99。短训 RL 没有损伤已有能力（对比 RLHF 的"对齐税"话题）。
4. **L4 纹丝不动（能力边界）**：0.00 → 0.00。两位数乘法需要多步进位乘法，超出 2.7M
   模型能力边界，**给奖励也学不会**——教科书级结论：RL 在能力边界内重排概率分布，
   不能凭空创造能力（与课件 grpo_arithmetic 的 L6 结论一致）。
5. **格式率 0 → 0（"RL 只优化被奖励的行为"的实证）**：本任务中模型几乎从不采样出
   `<answer>` 标签（格式奖励永远为 0，无梯度信号），所以格式率保持不变。
   这正是课件"只给正确分 → 格式率停在 0"消融实验的天然复现。
6. **训练动态**（train_curves.png）：40 步内正确分 0.77 → 0.91；策略熵 0.25 → 0.18
   （收敛为更确定性的策略）；KL 保持在 0.02~0.2（β=0.5 有效锚定参考模型）；
   零方差组比例随模型变强先升后降。40 步后 KL 爬升、熵回升 → 提前停止。

### 4.3 训练成本

| 阶段 | 耗时 | 说明 |
|---|---|---|
| SFT（750 步） | ~40s | 2.7M 参数，CPU |
| GRPO（40 步 × 8 题 × 8 采样） | ~45s | 每步 64 条补全生成 + 更新 |
| 评估（基线/复测各 300×4 题） | ~90s/次 | greedy + pass@8 + informative |
| **全流程** | **~5 分钟** | 一键 `bash run_all.sh` |

## 五、结论与思考

1. **GRPO 确实能提升小模型的数学能力**：在"算法已具雏形但概率不集中"的任务上，
   组相对奖励 + clip + KL 正则可以在几十步内把 greedy 正确率显著推高，且**只强化被奖励的行为**。
2. **RL 的收益边界清晰**：训练集内 +15pt、算法泛化 +9pt、能力边界 0 提升——
   "强化学习建立在模型基础能力之上才能有较好收益"（作业参考提示语）在本实验中完全成立。
3. **小模型 + 从零训练的独有挑战**（这也是与 0.5B 方案最大的不同）：
   - 深层模型 lr 过高会陷"位置捷径"学不到算法 → 需要更小的 lr；
   - 温度采样下"答案后继续输出"要求解析策略稳健（取第一个数字）；
   - 策略在能力边缘非常脆弱，GRPO 更新必须小步慢走（lr 1e-5 + 强 KL），
     且存在明显的"漂移-崩坏"提前停止点。
4. **可扩展方向**：增大组大小 K、格式奖励权重消融、K 对 advantage 估计质量的影响、
   更大模型/真实数据集（GSM8K）验证、多轮 R1 式 SFT+RL 迭代。
