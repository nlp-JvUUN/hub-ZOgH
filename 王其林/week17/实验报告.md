# 实验报告：基于 GRPO 的强化学习提升小模型数学解题能力

> 项目：`grpo_arithmetic` —— 在消费级显卡上用 GRPO + 可验证规则奖励训练 Qwen2-0.5B-Instruct 做算术题
> 数据来源：`outputs/baseline_probe.json`、`outputs/post_train_probe.json`、`outputs/post_train_probe_lora.json`、`outputs/train_log.json`、`outputs/train_log_lora.json`

---

## 一、实验概述

| 项目 | 内容 |
|------|------|
| 目标 | 验证 GRPO（Group Relative Policy Optimization）能否在无需人工标注、无奖励模型的条件下，显著提升小模型的算术计算正确率与输出格式遵循能力 |
| 基座模型 | Qwen2-0.5B-Instruct（bf16，24 层 × hidden 896，全量 checkpoint 约 988 MB） |
| 强化学习算法 | GRPO（TRL `GRPOTrainer`），KL 系数 β=0（不加载参考模型） |
| 任务 | 程序化生成的六档难度算术题（加减法 / 乘法，1~4 位整数运算） |
| 硬件 | RTX 4060 Laptop（8GB 显存）级消费设备即可完成全流程 |
| 训练规模 | 200 步优化步；每步 4 个 prompt × 组内采样 K=8 = 32 条补全 |
| 对照组 | ① 全量微调（494M 参数，196 秒，峰值显存 6.07 GB）② LoRA r=16（约 140 万参数 / 0.28%，668 秒，峰值显存 3.09 GB） |

**实验结论先行**：GRPO 将六档难度的平均 greedy 正确率从 **0.50 提升到 0.83**（LoRA 0.83），主训难度 L5「两位数×一位数」正确率 **0.20 → 0.90/0.92**，且提升泛化到了未进训练集的难度（如 L4 表内乘法 0.60 → 1.00）；但超出能力边界的 L6「两位×两位乘法」几乎学不动（0.08 → 0.24）。LoRA 用一半显存取得持平甚至略优的效果。

## 二、GRPO 算法原理

GRPO 是 DeepSeek 提出的策略优化算法（R1 的核心训练手段之一），与 PPO 相比的核心区别：

| 组件 | PPO (RLHF) | GRPO（本实验配置） |
|------|-----------|------------------|
| 价值网络 | 需要（critic 估计 baseline） | **不需要**：用组内奖励均值作 baseline |
| 奖励来源 | 独立训练的奖励模型 | **规则函数直接判定**（可验证奖励 RLVR）：答案精确匹配 |
| 参考模型 | 用于 KL 惩罚 | β=0 时完全省去，节省约 1 GB 显存与一半前向开销 |
| Advantage 计算 | GAE | $A_i = \dfrac{r_i - \text{mean}(r_{1..K})}{\text{std}(r_{1..K})}$，组内逐样本归一化 |

对同一 prompt 采样 K 条输出构成一个"组"，组内相对比较产生梯度：答得比别人好的样本被强化，答得差的被抑制。由此推出本实验最重要的方法论——**只有组内"有对有错"的 prompt 才产生学习信号**（全对或全错的组 advantage 全为 0）。

## 三、实验设计

### 3.1 任务定义与数据生成

系统提示词要求模型把最终答案放入 `<answer>42</answer>` 标签。六个难度级别程序化生成：

| 难度 | 运算类型 | 数值范围 | 定位 |
|------|---------|---------|------|
| L1_add_1digit | 个位数加法 | 1–9 | sanity check（预期太易） |
| L2_addsub_2digit | 两位数加减 | 10–99 | 训练集保底难度 |
| L3_addsub_3digit | 三位数加减 | 100–999 | 主训难度 |
| L4_mul_1digit | 表内乘法 | 2×2–9×9 | 留作泛化评估 |
| L5_mul_2x1digit | 两位×一位乘法 | 10–99 × 3–9 | 主训难度 |
| L6_mul_2x2digit | 两位×两位乘法 | 10–99 × 10–99 | 预期太难，验证能力边界 |

### 3.2 第一步：基线摸底，确定 GRPO 的"可学习甜区"

用 `probe_baseline.py` 对每档难度 50 题、温度采样 K=8 进行摸底（`baseline_probe.json`，greedy 正确率为宽松口径——输出最后一个数字即算对）：

| 难度 | greedy 正确率 | 温度采样正确率 | loose pass@8 | 有效组比例* | 结论 |
|------|:---:|:---:|:---:|:---:|------|
| L1 个位加法 | 0.94 | 0.88 | 1.00 | 0.44 | 太易：组内常全对，信号稀疏 |
| **L2 两位加减** | 0.76 | 0.65 | 0.94 | **0.74** | 保底（占训练集 25%） |
| **L3 三位加减** | 0.44 | 0.33 | 0.80 | **0.76** | 有效组比例最高 → 主训（50%） |
| L4 表内乘法 | 0.60 | 0.59 | 0.88 | 0.68 | 不进训练集，留作泛化评估 |
| **L5 两位×一位** | 0.20 | 0.23 | 0.64 | **0.62** | 提分空间大 → 主训（25%） |
| L6 两位×两位 | 0.08 | 0.04 | 0.20 | 0.20 | 太难：组内常全错，纯浪费算力 |

\* 有效组比例（informative group rate）：8 条采样中正确数介于 1~7 的 prompt 占比，即 GRPO 梯度的实际覆盖率。

两个关键基线事实：

1. **格式遵循近乎为零**：所有难度 greedy 格式率仅 0.00~0.04 —— 若正确分严格要求标签内取数，则冷启动时正确信号也为零。因此正确分采用**宽松解析**（有标签取标签内数字，否则取输出中最后一个数字），保证训练能启动。
2. **greedy 与 pass@8 存在巨大鸿沟**（如 L5：greedy 0.20 vs pass@8 0.64）—— 正确答案其实"藏在"模型的采样分布里但概率不高，这正是 GRPO 可以利用的"训练燃料"：RL 只需把分布质量向已存在的正确模式重排。

最终训练集：按 seed=123 程序生成 1000 条 prompt，难度配比 L3 : L5 : L2 = 50% : 25% : 25%；L1/L4/L6 不进训练集，专门回答"没训过的难度会不会也提升"。

### 3.3 复合奖励设计

```python
reward_total = reward_correct + 0.2 * reward_format

reward_correct ∈ {0, 1}   # 宽松解析正确性（保证冷启动有梯度）
reward_format  ∈ {0, 1}   # 输出含 <answer>N</answer> 标签（与正确性解耦）
```

设计意图：

- **解耦**：让"格式收敛"与"学会算对"成为两条可分别观测的训练曲线（TRL 对每个 reward 函数独立记录均值）；
- **权重 0.2 < 1.0**：故意制造主次信号竞争，观察弱信号在组内归一化下的命运（结果见 §5.6，这是一个超出预期的发现）；
- **宽松解析**：避免冷启动死锁（格式率为 0 时严格口径下组内奖励全 0 → advantage 全 0 → 无法启动）。

### 3.4 GRPO 训练配置与实施

| 配置 | 取值 | 说明 |
|------|------|------|
| `num_generations` (K) | 8 | 与基线摸底的 pass@8 口径一致 |
| KL 系数 β | 0.0 | 不加载参考模型，省显存；200 步短训练不需防漂移 |
| PPO-clip ε | 0.2 | 经典裁剪范围 |
| temperature | 1.0 | 保持组内多样性（多样性是 advantage 方差的来源） |
| max_completion_length | 64 | 答案仅几个 token |
| 批次 | 8 completions/微批 × 梯度累积 4 | 每步 = 4 prompt × 8 采样 = 32 条补全 |
| 学习率 | 全量 2e-6 / LoRA 2e-4 | LoRA 参数少故 lr 大 100 倍 |
| 步数 | 200 | epoch ≈ 0.8 |
| 两种参数高效方案 | 全量微调 494M 参数（196s，峰值 6.07GB）<br>LoRA r=16 target q/k/v/o_proj（≈1.4M 参数，668s，峰值 **3.09GB**） | 同一套奖励与数据，形成对照组 |

### 3.5 评估方案

- **同题配对对比**：训练前后均用 seed=42 生成同一批 6×50 道题，排除题目差异干扰；
- **三口径指标**：① 格式率（必须含 `<answer>` 标签）② strict 正确率（标签内数字正确）③ loose 正确率（最后一个数字正确，与训练奖励同口径）；
- **采样式指标**：pass@8、有效组比例随训练的变化；
- **对照维度**：训练集内难度（L2/L3/L5）vs 未训练难度（L1/L4/L6），区分"记题"与"能力泛化"。

## 四、实验过程中的关键工程问题

调试过程记录了多个实测定位的问题（详见代码注释与 `ARCHITECTURE.md`）：

| 问题现象 | 根因 | 解法 |
|---------|------|------|
| `import trl` 直接崩溃于 vllm 探测 | trl 0.21 调用 transformers 私有包探测函数；transformers 5.x 把返回值从 bool 改成 `(bool, version)` 元组，非空元组恒为真 → trl 误判所有可选依赖"已安装" | `src/trl_compat.py` 在导入 trl 前把元组返回值打补丁为真实布尔 |
| 训练 1 步后全部权重 NaN/Inf | 本地模型 config.json 标注 fp16 → 被静默加载为 fp16 → AdamW 的 eps=1e-8 及二阶动量在 fp16 下下溢为 0 → 0/0 = NaN | 显式 `model_init_kwargs={"torch_dtype": "bfloat16"}` |
| GRPO 采样补全全是乱码、奖励全 0 | transformers 5.x 下 gradient checkpointing + train 模式会损坏 generate 前向（对照实验定位） | 关闭 `gradient_checkpointing`（0.5B 模型显存够用） |

## 五、实验结果与分析

### 5.1 总体对比：训练前 vs 全量微调 vs LoRA（同一评估集，50 题/难度）

单元格格式：**基线 → 全量 → LoRA**

| 难度 | 在训练集 | 格式遵循率 | greedy 正确率（宽松） | pass@8（宽松） |
|------|:---:|:---:|:---:|:---:|
| L1 个位数加法 | — | 0.00 → 0.00 → **1.00** | 0.94 → 1.00 → 1.00 | 1.00 → 1.00 → 1.00 |
| L2 两位数加减 | √ | 0.02 → 0.06 → **1.00** | 0.76 → **1.00** → 0.98 | 0.94 → 1.00 → 1.00 |
| L3 三位数加减 | √ | 0.02 → 0.06 → **1.00** | 0.44 → 0.82 → 0.84 | 0.80 → 0.98 → 0.90 |
| L4 表内乘法 | — | 0.00 → 0.00 → **1.00** | 0.60 → **1.00** → 1.00 | 0.88 → 1.00 → 1.00 |
| L5 两位数×一位数 | √ | 0.00 → 0.00 → **0.98** | 0.20 → 0.90 → 0.92 | 0.64 → 0.96 → 0.96 |
| L6 两位数×两位数 | — | 0.04 → 0.08 → **1.00** | 0.08 → 0.24 → 0.24 | 0.20 → 0.32 → 0.32 |

汇总指标（六难度平均）：

| 平均指标 | 基线 | 全量 | LoRA |
|---------|:---:|:---:|:---:|
| greedy 正确率（宽松） | 0.50 | **0.83** | **0.83** |
| 训练集内三档平均正确率 | 0.47 | **0.91** | **0.91** |
| pass@8 | 0.74 | **0.88** | 0.86 |

### 5.2 发现一：能力甜区内提升显著且大幅泛化

1. **主训难度大幅提升**：L5 正确率 0.20 → 0.90/0.92（**4.5 倍**），pass@8 从 0.64 → 0.96；L3 从 0.44 → 0.82/0.84。
2. **跨难度泛化成立（不是背题）**：
   - L4（表内乘法，未进训练集）正确率 0.60 → 1.00，pass@8 达 1.00；
   - 未训练难度 L1 也顺势封顶。说明 RL 强化的是"做对算术"的一般内部回路，而非对训练表达式的记忆。
3. **能力边界外几乎不可学**：L6 仅 0.08 → 0.24，pass@8 只有 0.32。两位数×两位数的多次进位超出 0.5B 模型的表达边界——印证了教科书结论：**RL 是在模型既有能力边界内重排概率分布，不能凭空创造能力**。

典型样例对照（greedy 解码）：

| 题目 | 正确答案 | 基线输出 | 全量后 | LoRA 后 |
|------|:---:|------|------|------|
| 902 − 848 | 54 | `154` ✗ | `54` ✓ | `<answer>54</answer>` ✓ |
| 28 × 8 | 224 | `112` ✗ | `224` ✓ | `<answer>224</answer>` ✓ |
| 403 − 322 | 81 | `181` ✗ | `81` ✓ | `<answer>81</answer>` ✓ |
| 61 × 31 | 1891 | `901` ✗ | `1891` ✓ | `<answer>1891</answer>` ✓ |
| 23 × 9 | 207 | `871` ✗ | `197` ✗（边界题仍错） | `<answer>197</answer>` ✗ |

注意末行：个别基础题（L2 的 16+24）在全量后仍对，而 LoRA 出现了 `<answer>30</answer>` 的偶发退化（0.98 < 1.00）——这是 RL 收益伴随的小概率行为扰动。

### 5.3 发现二（超预期）：全量微调没学会输出格式，LoRA 双全收

- **全量微调**：正确率大涨，但所有难度的 greedy 格式率只停留在 ≤0.08，模型找到的局部最优是"直接输出裸数字"。训练日志佐证：`rewards/reward_format/mean` 全程 ≈ 0.01（几乎没有收敛），completion 平均长度约 4 个 token（裸数字）。
- **LoRA**：第 20 步左右格式分就打满（≈0.2/满分），训练结束格式率 0.98~1.00，strict 与 loose 正确率完全重合（说明"带标签"和"算得对"统一达成），completion 长度 ~10 token（恰好是一个 `<answer>N</answer>` 序列）。

原因分析（值得作为方法教训）：

1. **信号竞争下的归一化稀释**：advantage 由总奖励在组内归一化得到。正确分的方差量级是 ±1.0，格式分只有 ±0.2 且正确性越强两者越强相关——当模型大多答对时，带不带标签造成的组内排序变化很小，0.2 的增量不足以翻转相对优势。
2. **有效学习率差距**：LoRA 实际使用 2e-4（全量的 100 倍），微弱的边际信号需要更大的单步位移才能被采纳；这与 §5.2 中"全量 grad_norm 高频跳变至 30~94，LoRA 稳定在个位数"的现象一致。
3. **启示**：复合奖励各分量的目标强度需与优化器步长相匹配；若分量应同等学得，更稳妥的做法是对每个 reward 分量独立做组内归一化（Dr.GRPO 的思路），或调高弱信号权重（本项目留作消融方向）。

### 5.4 发现三：训练动态——熵坍缩与退化组比例

两条训练曲线（`train_log*.json`，曲线图见 `outputs/figures/train_curves.png`）的关键节点：

| 指标 | 全量（step 5 → 20 → 200） | LoRA（step 5 → 20 → 200） |
|------|------|------|
| 正确分均值 | 0.59 → **0.95** → 0.88 | 0.75 → 0.92 → **0.96** |
| 格式分均值 | 0.01 → 0.00 → 0.01（未启动） | 0.00 → **0.20（满）** → 0.20 |
| frac_reward_zero_std | 0.15 → 0.85 → 0.60 | 0.35 → 0.90 → 0.80 |
| 策略熵 | 0.49 → 0.13 → 0.11 | 0.30 → 0.04 → **0.01** |
| 补全平均长度（token） | ~5 | ~10 |

解读：

1. **正确分快速爬坡后高位震荡**：早期最容易赢的模式（简单题）先饱和，中期震荡来自中等题（L3/L5）上的持续攻防，符合"先吃掉低垂果实"的 RL 动态。
2. **frac_reward_zero_std 是 GRPO 的晴雨表**：其上升说明越来越多组的 8 条采样全对/全错（advantage 归零），后期全量 0.6~0.85、LoRA 0.8 左右——训练效率在衰减，若继续加长训练应换入更难的题目或降低 temperature 维持探索。
3. **熵坍缩警示**：两种方案都迅速退化为近确定性策略，LoRA 尤甚（0.30 → 0.01，几乎零探索）。好处是任务表现稳定上限高；隐患是探索枯竭后无法继续改进。长训练需监控 entropy 曲线并配合熵正则 / 更高温度 / larger group K。

### 5.5 成本效益：LoRA 显存减半、效果反超

| 维度 | 全量微调 | LoRA (r=16) |
|------|---------|-------------|
| 峰值显存 | 6.07 GB | **3.09 GB（≈一半）** |
| 训练时间（200 步） | **196 秒** | 668 秒 |
| 可训练参数 | 494M（100%） | ≈1.4M（**0.28%**） |
| checkpoint 体积 | 988 MB | **8.7 MB（adapter）** |
| 最终效果 | 正确率小幅领先的题目为零，格式≤8% | 正确率持平（训练集内平均还高 0.7pp），**格式 1.00 全面领先** |

在本任务场景（0.5B 小模型 + 短训练 + 可验证奖励）中，**参数少不等于效果差**：LoRA 的强正则效应抑制了全量大梯度的噪声抖动，同时更高的等效学习率让弱信号也能被采纳。这是性价比最高的选择，仅需留意熵枯竭问题。

## 六、结论

1. **有效性**：GRPO + 规则可验证奖励在没有奖励模型、没有人工标注、没有参考模型的极简配置下，200 步（分钟级训练成本）将 Qwen2-0.5B 六难度平均算术正确率 0.50 → 0.83，主训难度最高提升 4.5 倍，成功复现了 R1 式"用 RL 点燃小模型"的最小可行路径。
2. **泛化边界清晰**：能力边界内的任务（包括从未出现在训练集中的 L4）普遍受益，边界外的 L6 学不动——**RL 重排概率分布而非创造能力**，这决定了 RL 应部署在模型"偶尔能做对"的任务区间。
3. **选题方法是成败关键**：用基线的 informative group rate 刻画甜区（L3=0.76 主训），太易/太难的难度不进训练集，直接决定了有限算力的转化率。
4. **奖励塑形要考虑归一化动力学**：弱权重格式分在全量微调的低学习率下完全未被采纳，而在 LoRA 的高等效学习率下迅速收敛——多分量奖励要么独立归一化，要么权重需与学习率联合调参。
5. **工程教训**：fp16/eps 下溢导致一步 NaN、gradient checkpointing 污染 generate、trl×transformers 版本兼容三大坑都已实测定位并固化到 `trl_compat.py` 与训练配置中。
6. **后续消融方向**：提高格式分权重至 1.0 观察信号竞争反转；删除 reward_format 验证"RL 只优化被奖励的行为"；把 L6 拆分为中间档课程；K=4/16 对 advantage 估计质量的敏感性；更长训练下监控熵并引入熵正则。
