# 基于简历模板生成简历（自包含 skill）

## 目标

基于内置简历模板生成一份结构完整、亮点突出、量化充分的简历。严格遵循模板的章节结构与字段框架，不脱离模板自行发挥。

本 skill 完全自包含：模板、字段清单、PDF 导出脚本都在 skill 目录内，复制到任何项目/目录即可直接使用，不依赖外部文件。

## 核心文件（本 skill 目录内）

- **模板**：`templates/resume-template.md`（`{{占位符}}` 形式标识待替换字段，已内置「强动词 + 量化」行文框架）
- **待收集字段清单**：`references/template-fields.md`（按章节分组的占位符清单）
- **导出脚本**：`scripts/md_to_pdf.py`（Markdown → PDF / HTML / Word / Markdown，跨平台自动检测中文字体）
- **样式配置**：`scripts/styles.json`（内置 classic 经典、modern 简约现代两套排版，可扩展）
- **自动化测试**：`scripts/test_skill.py`（跑全套导出 + 校验，见「测试」）
- **示例输出**：`examples/resume-example.md`（可选，**虚构数据**，仅演示如何把占位符改写为「强动词 + 量化」的经历条目）

> 若运行目录存在自定义 `简历模板.md`，可优先使用它作为模板覆盖（project-local 定制场景）；默认使用 skill 内置模板。

## 工作流程

### 1. 读取模板

读取本 skill 内置的 `templates/resume-template.md`；若运行目录存在自定义 `简历模板.md` 则改读它。若用户同时提供已有简历，以其为信息源，按模板章节重新组织内容。

### 2. 收集信息

模板中的占位符即待收集字段清单（见 `references/template-fields.md`）。按分组向用户收集：

- **基本信息**：姓名、性别、年龄、电话、邮箱、工作年限、求职意向、期望薪资、期望城市
- **个人优势**：核心框架/技术栈、使用年限、参与项目数量、框架底层原理、工程化与规范工具、编程语言、相关技术
- **工作经历**：每段经历的公司、职位、起止时间，以及对应模板条目的职责与量化成果（强动词 + 数字）
- **教育经历**：学校、学历、专业、起止时间

约束：

- 每次最多询问 3 个问题（与 agent 身份规则一致），分批收集，不要一次性抛出一长串问卷。
- **不编造**用户的经历、数据或证书。缺失信息标注「待补充」，不得凭空补全。
- **主动引导量化**：用户没说数字时，追问具体量化结果（「这个项目服务多少用户 / 性能提升多少 / 覆盖多少业务模块？」，而不是等用户自己想起）。量化是这份模板的竞争力所在。
- **JD 匹配（可选）**：若用户提供了目标岗位 JD，把它纳入收集与改写依据——识别 JD 的关键词/技术栈，在个人优势与工作经历中自然落位，提高匹配度。无 JD 时保持通用写法。

### 3. 生成简历

严格按模板章节输出 Markdown：

- 替换全部 `{{占位符}}` 为用户真实信息。
- 工作经历条目按模板保留的「强动词 + 量化结果」行文框架改写为真实经历，而不是逐字保留占位符句子。
- 保持模板的排版：姓名 `#` 一级标题、`**加粗**` 联系方式行、`---` 分隔线、`##` 章节、`### 公司　职位　起止时间`、`-` 条目。
- 在 Markdown 顶部以 `<!-- 待确认项：... -->` HTML 注释列出缺失或待用户确认的字段（不显示在渲染结果中）。

### 4. 自检

生成后从四个维度检查并优化：

- **结构完整性**：头部 → 个人优势 → 工作经历 → 教育经历，章节齐全；`{{...}}` 占位符无残留。
- **表述专业性与量化**：每条工作经历以强动词开头，含具体数字（数量、指标、时长等）；遵循 STAR（情境-任务-行动-结果）框架。
- **岗位匹配度**：突出与求职意向/目标岗位相关的技能、关键词与成果。
- **排版格式**：Markdown 层级与模板一致，中英文混排规范。

### 5. 输出与导出

- 默认输出 Markdown 全文（便于预览）。
- 用户要求 **PDF / Word / HTML** 时，用导出脚本生成，命令统一：

```
python <skill-dir>/scripts/md_to_pdf.py <resume.md> [output] \
    [--format pdf|html|docx|md] [--style classic|modern] \
    [--font <path> | --font-dir <dir>] [--check-only]
```

- **格式**：`--format` 指定（pdf / html / docx / md）；不给时按输出文件扩展名推断，再否则默认 pdf。`md` 只输出规范化 Markdown。
- **样式**：`--style classic|modern` 切换排版（内置 `scripts/styles.json`，可自行加主题或用 `--styles <file>` 覆盖）。页边距、字号、颜色、行距、项目符号大小全部由样式配置控制。
- **自检**：脚本自动拒绝含残留 `{{占位符}}` 的输入（exit 2）；`--check-only` 只做校验不产出文件。
- **字体**：跨平台自动检测中文字体（Windows simhei/msyh、macOS PingFang、Linux Noto CJK/文泉驿），检测不到时用 `--font` 指定。PDF 自动子集化字体（几十 KB）。多页简历自动加页码。
- **依赖**：PDF/HTML 需 `pymupdf`（`pip install pymupdf`）；Word 需 `python-docx`（`pip install python-docx`）。
- **LaTeX**：可调用 `resume-assistant` 技能的 export 命令。

### 6. 测试

改动导出脚本后，运行 `python <skill-dir>/scripts/test_skill.py` 确认全绿（20 项断言：无残留占位符、PDF 页边距合法、单字体渲染、HTML/Word 内容完整、样式切换正常）。

## 写作规范（工作经历条目）

每条遵循「强动词 + 对象 + 方式 + 量化结果」：

- 强动词：主导 / 负责 / 设计并落地 / 实现 / 搭建 / 优化 / 封装 / 推动…
- 量化：项目数量、性能指标、节点数、工具数、服务规模、时间跨度等具体数字。
- 不编造：数字与事实必须来自用户输入；缺失的数字标注「待补充」。

## 自检清单

- [ ] 头部信息完整（姓名 / 联系方式 / 工作年限 / 求职意向 / 期望薪资 / 期望城市；缺失项标「待补充」）
- [ ] 个人优势 5 条左右，每条含技术栈与量化支撑
- [ ] 工作经历按公司分段，每段含「强动词 + 量化」条目，无占位符句子残留
- [ ] 教育经历完整（学校 / 学历 / 专业 / 起止时间）
- [ ] 全文无 `{{...}}` 占位符残留
- [ ] 无编造数据，所有数字可追溯至用户输入
- [ ] 顶部「待确认项」注释与实际缺失字段一致
