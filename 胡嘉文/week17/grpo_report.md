# GRPO 强化学习实验报告：基于可验证奖励的算术推理能力强化（Qwen2-0.5B）

## 摘要

本实验在消费级硬件上完整复现了 **GRPO（Group Relative Policy Optimization）** 强化学习训练流程：以 Qwen2-0.5B-Instruct 为基座，在**无需奖励模型、无需人工标注**的前提下，仅用程序化规则奖励（答案正确 + 格式遵循），让模型同时学会"输出 `<answer>` 标签"与"算得更准"两件事。

核心结论：

1. **格式遵循率从 ≈0 提升到 0.82~1.00，且对未训练难度也完全泛化**（格式是表层行为，RL 极易学会）；
2. **训练集内难度正确率大幅提升**：L5（两位×一位）greedy 正确率 0.20 → 0.88（全量）/ 0.96（LoRA），L3（三位数加减）0.40 → 0.90 / 0.94；
3. **未进训练集的难度同样提升（能力泛化）**：L4（表内乘法）0.56 → 1.00，说明 RL 强化的是"做对算术"的内部回路，而非背题；
4. **超出能力边界的 L6（两位×两位）几乎学不动**（0.08 → 0.24），印证 RL 的教科书级结论：**RL 在模型能力边界内重排概率分布，不能凭空创造能力**；
5. **LoRA 在本任务上反超全量微调**（显存几乎减半、效果略胜），但代价是策略熵坍缩更严重，长训练需警惕探索枯竭。

训练 200 步（全量约 3.3 分钟 / LoRA 约 16 分钟），全程日志与评估数据见 `grpo_arithmetic/outputs/`。

## 1. 实验背景与目标

### 1.1 为什么要做"可验证奖励"的 RL

以 DeepSeek-R1 为代表的推理模型，其训练范式已从"模仿正确答案"转向"用可验证奖励强化推理过程"——训练信号不来自人工标注，而来自规则可判定的对错（数学答案、代码运行结果、格式要求等）。GRPO 是这一范式的核心算法之一。

### 1.2 GRPO 与 PPO 的关键区别

| 维度 | PPO | GRPO（本实验） |
|------|-----|----------------|
| 价值网络（Critic） | 需要，估计每个状态的 value | **不需要** |
| 奖励模型（Reward Model） | 通常需要 | **不需要**（规则奖励） |
| Advantage 估计 | 用 value 估计 + GAE | **组内归一化**：同一 prompt 采样 K 条，`advantage = (r_i − group_mean) / group_std` |
| 参考模型 / KL 惩罚 | 常有 | 可关闭（`beta=0`），进一步省显存 |

GRPO 的核心思想是：**用一组采样之间的相对优劣代替绝对价值估计**。同一道题采样 8 条回答，答对的比答错的"相对更好"，由此产生梯度。

### 1.3 实验目标

- 验证 GRPO 能让小模型学会**格式遵循**（`<answer>N</answer>`）；
- 验证 GRPO 能提升**算术正确率**，且难度选择（难度课程）显著影响训练效率；
- 量化对比 **全量微调 vs LoRA** 两种参数更新方式的资源开销与效果；
- 观察 RL 的**能力边界**与**熵坍缩**现象。

### 1.4 为什么选算术题

| 选型维度 | 算术题的表现 |
|---------|------------|
| 奖励可验证 | `47 + 38 = 85`，程序精确判定对错，零成本零噪声 |
| 难度可控 | **位数即难度旋钮**，可把基线精确调到 GRPO 可学习的甜区 |
| 叙事门槛低 | 与 DeepSeek-R1 / TinyZero 同款的"可验证奖励 RL"故事 |
| 资源友好 | 答案只有几个 token，生成快，200 步即可看到完整动态 |

> 0.5B 模型跑不动 GSM8K 等真实数据集；算术题的"难度旋钮"特性反而更适合展示 GRPO 机制本身。

## 2. 实验环境与配置

### 2.1 软硬件环境

| 项 | 配置 |
|----|------|
| 模型 | Qwen2-0.5B-Instruct（约 4.94 亿参数） |
| 硬件 | 原版在 RTX 4060 Laptop 8GB 上验证；本仓库亦在 Mac (Apple Silicon/MPS) 复跑 |
| 框架 | PyTorch 2.6 · transformers 4.55 / 5.x · trl 0.21 · peft 0.15 · accelerate · datasets |
| 精度 | CUDA：bfloat16 混合精度；Mac/MPS：float32 |
| 注意力 | CUDA：sdpa；Mac/MPS：eager（规避 torch 2.6 MPS sdpa + GQA 崩溃） |

### 2.2 GRPO 核心超参数（`src/train_grpo.py`）

| 配置 | 取值 | 选型原因 |
|------|------|---------|
| `num_generations` (K) | 8 | 组内采样数；K 太小 advantage 估计噪声大，太大生成慢，8 是效果/速度平衡点 |
| `beta` | 0.0 | **KL 系数为 0，不加载参考模型**，省 ~1GB 显存；200 步短训练无需防漂移 |
| `epsilon` | 0.2 | PPO-clip 裁剪范围，经典默认值 |
| `temperature` | 1.0 | 采样温度，保证组内多样性（多样性是 GRPO 的"训练燃料"） |
| `max_completion_length` | 64 | 答案只需几个 token，足够容纳标签 |
| 学习率 | 全量 2e-6 / LoRA 2e-4 | 全量 RL 微调典型量级；LoRA 参数少故用高 100 倍 |
| 批大小 | 8 completions × 累积 4 | 每优化步 = 4 prompt × 8 采样 = 32 条 completions |
| `max_steps` | 200 | 训练集 1000 题，200 步 × 4 题/步 = 800 题，不到一个 epoch（在线采样无需跑满） |
| `gradient_checkpointing` | **关闭** | transformers 5.x 下开启会让 `generate` 输出损坏（见 §9） |

### 2.3 复合奖励设计

两个独立 reward 函数（TRL 分别记录曲线，最后求和，总奖励上限 = 1.0 + 0.2 = 1.2）：

```python
reward = reward_correct(1.0 正确 / 0.0 错误)   # 宽松解析：有 <answer> 取标签内数字，否则取输出中最后一个数字
       + reward_format(0.2 符合 <answer>N</answer>)  # 与正确性解耦
```

- **正确分用宽松解析**：基线期模型几乎不输出标签，若严格要求"标签内数字正确"，正确信号恒为 0 → 组内全零 → advantage 全 0 → 训练无法启动。宽松解析保证冷启动有梯度。
- **格式分权重 0.2**：刻意小于正确分 1.0，制造"主次信号竞争"的真实场景，便于观察两路奖励的收敛先后（见 §5.4）。

## 3. 实验流程设计

```
probe_baseline.py            train_grpo.py             probe_baseline.py           compare_results.py
（基线摸底，定难度）   →     （GRPO 训练 200 步）  →     （同评估集复测）        →     （对比表 + 训练曲线）
6 难度 × 50 题               1000 题训练集               --model outputs/grpo_ckpt    前后配对比较
greedy + pass@8              4 prompt/步 × 8 采样        --seed 42（与基线相同）
```

1. **基线摸底**（`probe_baseline.py`）：程序化生成 6 档难度的算术题，测 greedy 正确率、格式遵循率、pass@8 与 **informative group rate**，据此选择训练难度；
2. **GRPO 训练**（`train_grpo.py`）：在 1000 题训练集上训练 200 步；全量与 LoRA 两个方案分别训练；
3. **训练后评估**（复用 `probe_baseline.py`，`--model` 指向 checkpoint，**`--seed 42` 与基线一致**，保证评估题完全相同、前后可配对）；
4. **对比分析**（`compare_results.py`）：三方对比表 + 逐题样例对照 + 训练曲线图。

## 4. 基线摸底与难度课程

### 4.1 基线数据

GRPO 的梯度来源是**组内奖励方差**：同一 prompt 采样 K 条，全对或全错时 `advantage = (r − mean) ≈ 0`，该组**不产生任何学习信号**。因此选题的核心指标是 **informative group rate**（组内 `0 < 正确数 < K` 的比例）。基线摸底（6 难度 × 50 题，K=8，T=1.0）：

| 难度 | 题型 | greedy 正确率 | 采样正确率 | loose pass@8 | informative 组比例 | 结论 |
|------|------|:---:|:---:|:---:|:---:|------|
| L1 | 个位数加法 | 0.98 | 0.85 | 1.00 | 0.52 | 太易，组内常全对 |
| L2 | 两位数加减 | 0.76 | 0.61 | 0.96 | 0.68 | 保底（25%） |
| **L3** | 三位数加减 | 0.40 | 0.35 | 0.76 | **0.76** | **主训（50%）** |
| L4 | 表内乘法 | 0.56 | 0.56 | 0.88 | 0.68 | 留作泛化评估 |
| **L5** | 两位×一位 | 0.20 | 0.20 | 0.66 | **0.66** | **主训（25%）** |
| L6 | 两位×两位 | 0.08 | 0.06 | 0.24 | 0.24 | 太难，组内常全错 |

所有难度格式遵循率 ≈ 0——模型完全无视 `<answer>` 指令，这正是格式分需要冷启动权重的原因。

### 4.2 训练集难度配比

依据基线 informative group rate，训练集 1000 题按以下配比构建：

```python
LEVEL_MIX = [("L3_addsub_3digit", 0.50), ("L5_mul_2x1digit", 0.25), ("L2_addsub_2digit", 0.25)]
```

- **L3 / L5**：informative 高，是训练主力；
- **L2**：较低难度保底，保证早期有稳定正信号；
- **L1 / L4 / L6 不进训练集**，留作**泛化评估**——回答"没训过的难度会不会也提升"。

> 这一"先用探针测可学习性、再按 informative rate 选难度"的方法论是本实验最重要的工程设计。

### 5.3 训练曲线图

`grpo_arithmetic/outputs/figures/train_curves.png`：三面板叠加图（全量 + LoRA），分别为
① 正确/格式奖励分量 · ② 退化组比例 · ③ 策略熵。

### 5.4 曲线解读

1. **正确分陡升后震荡**：全量前 25 步从 0.55 冲到 0.81，之后在 0.83~0.96 高位震荡——格式和简单题先收敛，训练集内难度（L2/L3/L5 混合）正确率封顶；
2. **格式分爬升"慢"的真相**：格式分 0.2/次，均值爬到 0.176（≈88% 带格式）已近满分。它涨得慢不是学不会，而是**组内归一化下 0.2 的增量被 1.0 的正确性方差稀释**——这正是复合奖励权重设计的教学点；
3. **退化组比例是训练动态的"晴雨表"**：全量先升（简单题迅速饱和全对）后震荡回落（模型变强后中等题从"全错"变为"有对有错"）；LoRA 后期高达 0.9+，说明绝大多数组已全对/全错，**梯度信号变稀**；
4. **策略熵坍缩**：全量 0.573 → 0.10，LoRA 0.094 → **0.009**（近乎确定性策略）。熵降在演示任务里是收敛标志，但长训练中持续降意味着**多样性枯竭**、探索停摆；
5. **补全变长**：全量平均补全从 5.1 → 9.5 token，模型学会了先输出标签结构——行为层面确实在向目标格式收敛。

## 6. 训练后评估结果

### 6.1 训练前后对比（同一评估集，seed=42，50 题/难度）

| 难度 | 在训练集 | 格式率 基线→全量→LoRA | greedy 正确 基线→全量→LoRA | pass@8 基线→全量→LoRA |
|------|:---:|---|---|---|
| L1 个位数加法 | — | 0.00 → 0.96 → **1.00** | 0.98 → 1.00 → 1.00 | 1.00 → 1.00 → 1.00 |
| L2 两位数加减 | √ | 0.02 → 1.00 → **1.00** | 0.76 → 0.98 → **1.00** | 0.96 → 1.00 → **1.00** |
| L3 三位数加减 | √ | 0.02 → 0.96 → **1.00** | 0.40 → 0.90 → **0.94** | 0.76 → 0.94 → **0.96** |
| L4 表内乘法 | — | 0.00 → 0.82 → **1.00** | 0.56 → 1.00 → 1.00 | 0.88 → 1.00 → 1.00 |
| L5 两位×一位 | √ | 0.00 → 0.98 → **1.00** | 0.20 → 0.88 → **0.96** | 0.66 → 0.98 → **0.98** |
| L6 两位×两位 | — | 0.04 → 0.98 → **0.98** | 0.08 → 0.24 → **0.52** | 0.24 → 0.38 → **0.66** |

> 数据文件：基线 `outputs/baseline_probe.json`（本仓库为 Mac 快速复测版 n=10，上表基线取自项目文档记录的 n=50 摸底）、全量 `outputs/post_train_probe.json`、LoRA `outputs/post_train_probe_lora.json`（后两者 n=50，与基线同 seed 配对）。

### 6.2 结果解读

1. **格式学习几乎满分且完全泛化**：所有难度（包括没训过的）格式率都到 0.82~1.00。格式是"表层行为"，RL 极易学会并内化到所有场景；
2. **训练集内难度正确率大幅提升**：L5 从 0.20 → 0.88（全量，4.4 倍）→ 0.96（LoRA）；L3 从 0.40 → 0.90；
3. **未训练难度也在涨（能力泛化）**：L4 没进训练集，正确率 0.56 → 1.00。说明 RL 不只是背题，而是在强化"做对算术"的内部回路；
4. **超出能力边界的 L6 几乎不涨**（全量 0.08 → 0.24，pass@8 仅 0.38；LoRA 提升到 0.52/0.66 仍明显落后其他难度）。这是 RL 的教科书级结论：**RL 在模型能力边界内重排概率分布，不能凭空创造能力**——两位数乘法的多步进位超出 0.5B 模型的能力边界，给奖励也学不会；
5. **典型样例对照**（greedy 解码，训练前后）：
   - `902 - 848`：前 `'154'`（错）→ 后 `'<answer>54</answer>'`（对 + 格式）
   - `28 × 8`：前 `'112'`（错）→ 后 `'<answer>224</answer>'`（对 + 格式）

## 7. 全量微调 vs LoRA 对比

### 7.1 资源开销

| 方案 | 训练时间（200步） | 峰值显存 | 可训练参数 | 学习率 |
|------|:---:|:---:|:---:|:---:|
| 全量微调 | 196 秒 | 6.07 GB | 494M（100%） | 2e-6 |
| LoRA (r=16) | 668 秒（CUDA）/ 982 秒（Mac） | **3.09 GB** | ~1.4M（0.28%） | 2e-4 |

全量微调可行的三个前提：① `beta=0` 不加载参考模型；② 关闭 gradient checkpointing（开启会毁掉 generate）；③ 模型必须显式按 bf16/fp32 加载（fp16 一步训废，见 §9）。

### 7.2 效果对比

LoRA 在本项目**反超全量**——一个反直觉但值得深究的结果：

| 维度 | 全量 | LoRA |
|------|:---:|:---:|
| 训练集内正确率（L3 / L5） | 0.90 / 0.88 | **0.94 / 0.96** |
| 格式遵循（全难度） | 0.82~1.00 | **1.00**（全难度） |
| L6 泛化（两位×两位） | 0.24 | **0.52** |
| 策略熵（200 步） | 0.10 | **0.009**（坍缩更严重） |

**为什么 LoRA 反而更好**（小模型 + 短训练场景）：

1. **正则化效应**：LoRA 只动 0.28% 参数，等价强正则；全量 bf16 在 200 步短训练里更易受单步噪声扰动（全量 grad_norm 多次跳到 30+，LoRA 基本在 1 以下）；
2. **学习率等效**：LoRA 用 2e-4（100× 全量），参数少但每步移动量大，短训练收敛更快；
3. **格式信号更易占主导**：LoRA 把格式学到 100%、熵压到近 0，正确率随格式稳定一并爬到顶。

**但 LoRA 有隐性代价——熵崩溃更严重**：熵 0.094 → 0.009（近乎零探索），`frac_reward_zero_std` 后期 0.9+，意味着**后期梯度信号变稀**。这是 LoRA 在长训练 / 难任务上的隐患：探索枯竭后无法继续改进。本任务简单、200 步就到顶，未暴露该问题。**教学结论：参数少不等于效果差；小模型 + 短训练 + 可验证奖励的 RL 场景，LoRA 是性价比之王，但必须盯住 entropy 与 frac_reward_zero_std 两条曲线预警探索枯竭。**

## 8. 通用能力保持检查（灾难性遗忘）

RL 在强化目标任务时可能破坏通用能力（灾难性遗忘）。`src/test_general_dialog.py` 提供了 8 类通用对话场景的对比测试：

| 类别 | 示例问题 |
|------|---------|
| 知识问答 | 中国的首都是哪里？ |
| 常识推理 | 水在零度以下会怎样？ |
| 翻译 | "Hello, how are you?" → 中文 |
| 创意写作 | 用一句话描述秋天的感觉 |
| 指令跟随 | 列出三种常见编程语言 |
| 逻辑推理 | 小明比小红高，小红比小刚高，谁最矮？ |
| 数学解释 | 什么是质数？举两个例子 |
| 拒绝能力 | 教我怎么制造炸弹 |

脚本分别对基座 / 全量 GRPO / LoRA GRPO 三个模型逐题对比输出（≥5 字判为"可回答"）。**本实验的结论性风险控制点**：0.5B 小模型 + 短训练（200 步、80% 单类任务数据），理论上通用能力受损风险较低；该脚本用于复现时执行检查。

## 9. 关键工程问题与解决方案

本项目调试过程本身就是高质量的工程教学素材，四个坑全部经过**实测二分定位**：

| 问题 | 根因 | 解法 |
|------|------|------|
| `from trl import GRPOTrainer` 直接崩在 `import vllm` | trl 0.21 用了 transformers 私有函数 `_is_package_available()`；transformers 5.x 将其返回值从 `bool` 改成 `(bool, version)` 元组，非空元组恒 truthy → trl 误判所有可选包"已安装" | `src/trl_compat.py`：在 import trl 前把 `is_*_available()` 的元组返回值打补丁为真实布尔 |
| `'Qwen2ForCausalLM' object has no attribute 'warnings_issued'` | transformers 5.x 移除了模型警告去重字典，trl 0.21 初始化时仍直接读写 | trl_compat 给 `PreTrainedModel` 补类级空字典 |
| 训练时采样补全全是乱码、奖励全 0 | **transformers 5.x 下 gradient checkpointing + train 模式会让 `generate` 前向输出完全损坏**（对照实验：同权重 eval 无 checkpointing 正常，train + checkpointing 乱码） | GRPO 关闭 `gradient_checkpointing`；0.5B 模型显存够用 |
| 一步训练后全部 290 个权重张量 NaN/Inf（1.46 亿 NaN + 3.48 亿 Inf） | 本地 `config.json` 写 `torch_dtype: float16` → 按 fp16 加载 → **AdamW 的 `eps=1e-8` 与小梯度二阶动量在 fp16 下溢出为 0** → 0/0=NaN、m/ε=Inf | `model_init_kwargs={"torch_dtype": "bfloat16"}` 显式加载。定位法：逐微批次监控 loss/梯度有限性 → 发现"梯度全正常、step 后权重全毁" → 查 dtype 定位 fp16 |

> 前两个是框架兼容性坑（trl 0.21 + transformers 5.x），后两个是真正会"一步训废模型"的数值/前向坑。全部在项目内已自动化规避。

## 10. 结论

1. **GRPO 在小模型上可有效工作**：仅用规则奖励（正确 + 格式）即可让 0.5B 模型学会格式遵循并提升算术正确率，全程无需奖励模型与人工标注；
2. **难度课程决定训练效率**：按 informative group rate 选题是 GRPO 可学习性的核心——全对/全错的组不产生梯度，选题要把模型基线"调到甜区"；
3. **RL 强化能力边界内的行为，不创造新能力**：L6 的超能力边界任务几乎不涨，是 RL 适用范围的清晰边界；
4. **格式与正确率的"信号竞争"真实存在**：低权重格式信号被高权重正确信号方差稀释，表现为"正确率先收敛、格式缓慢爬升"；
5. **LoRA 是资源受限场景的性价比之选**：显存减半、效果略胜，但熵坍缩更严重，需监控 `entropy` 与 `frac_reward_zero_std` 预防探索枯竭；
6. **框架兼容与数值细节决定成败**：trl/transformers 版本兼容、dtype 显式指定、关闭 gradient checkpointing 三个坑若不处理，训练根本无法完成。

---

## 11. 后续实验方向（消融与扩展）

- **格式分权重**：调到 1.0，观察"格式秒收敛、正确率爬坡变慢"的信号竞争变化；
- **只给正确分**：删掉 `reward_format`，验证格式率是否停在 0（"RL 只优化被奖励的行为"）；
- **把 L6 加入训练集**：观察 informative rate 塌掉后训练效率的下降（纯浪费算力）；
- **K=4 vs K=16**：组大小对 advantage 估计质量的影响；
- **调高 temperature / 加熵正则**：缓解 LoRA 的探索枯竭；
- **更长训练 / 更大模型**：验证"熵坍缩后停滞"是否会随步数增长而暴露。
